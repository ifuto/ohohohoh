# Rsift (RsGraphics) 理論ベンチマーク — メモリ圧縮量・FPS 向上(%)

**制定: 2026-08-03 (wave 220 HQ 直後) / 実施: Arena エージェント**
**対象: arena/019fc7cc-rsift @ 3aaddf3 (wave 220 HQ)**
**分類: `internal/` (プロジェクトオーナー専用・精密導出を含む)**

> 本書は疑似 Minecraft ハーネス (`examples/pseudo_mc_rd24.rs` / `pseudo_mc_bench.rs`)
> 上の**実測値**から、**理論上のメモリ圧縮量と FPS 向上(%)** を**機械演算**で導出した。
> A = Vanilla 系 (32B/頂点 + smooth AO) / B = Sodium 系 (実ソース `mc1.21.11-0.8.13`
> 準拠 20B/頂点) / C = Rsift (12B/頂点 + Tipsify + 形状キャッシュ)。
> **全数値は Python による実測からの演算 (暗算・推測なし)**。ソース対抗 (B) は
> Sodium 実ソース準拠の Rust 再現モデル (実バイナリ実行ではない — §6 制約)。

## 1. ヘッドライン (RD24 = 2,401 チャンク = CaffeineMC 公式測定条件)

| 指標 | Vanilla (A) | Sodium (B) | **Rsift (C)** | C の優位 |
| :-- | --: | --: | --: | :-- |
| **頂点バッファ (VRAM)** | 1.576 GB | 985.1 MB | **233.3 MB** | **A 比 −85.2% / B 比 −76.3%** |
| **セクション実体メモリ** | 236.0 MB (u16 flat) | 同左 | **17.1 MB** (palette) | **−92.8%** |
| **CPU 律速 理論 FPS** | 27.7 FPS | 26.5 FPS | **41.5 FPS** | **A 比 +49.8% / B 比 +56.8%** |
| 頂点数 (GPU 負荷代理) | 49.26 M | 49.26 M | **19.44 M** | **−60.5%** |
| リージョン I/O | 3,281 ms (zlib) | 同左 | **586.7 ms** (zstd) | **5.59x** |
| ACMR (cache 16) | 1.672 | 1.672 | **1.030** | **−38.4%** |
| draw call (可視 14 sec) | 8 | 2 | **2** | **A 比 −75%** |

**一句結論**: 描画距離 24 (公式条件) で、頂点メモリは Sodium 比 **76.3% 減**、
CPU 律速 FPS は **+56.8%** (理論)。GPU 帯域律速なら上界は更に大きい (§4)。

## 2. メモリ圧縮量 (実測・スケール別)

頂点バッファサイズ = 頂点数 × バイト/頂点 (intern 重複排除後の C 頂点数を含む)。

| スケール | 対抗 | Vanilla/Sodium | **Rsift** | 圧縮後比率 | **削減量** |
| :-- | :-- | --: | --: | --: | --: |
| **RD24** (2,401c) | vs A | 1,576,230,656 B | 233,313,648 B | 14.8% | **−1.343 GB** |
| **RD24** (2,401c) | vs B | 985,144,160 B | 233,313,648 B | 23.7% | **−751.8 MB** |
| **36c** | vs A | 27,572,992 B | 3,646,740 B | 13.2% | **−86.8%** |
| **36c** | vs B | 17,233,120 B | 3,646,740 B | 21.2% | **−78.8%** |

セクション実体 (ブロック状態配列) の palette 圧縮:

| スケール | u16 flat | **palette_pack** | 比率 | 削減 |
| :-- | --: | --: | --: | --: |
| RD24 | 236,027,904 B | 17,063,770 B | **7.23%** | −92.8% |
| 36c | 3,538,944 B | 248,110 B | **7.01%** | −93.0% |

> palette 圧縮率はスケール非依存 (≈7%、シェアしないブロック状態種類数で決まる)。
> 頂点圧縮は 12B/頂点 (B の 20B 比 0.6×/頂点) × intern 重複排除 (頂点数 0.395×)
> の積 = 0.237× (B 比)。両軸の積で B 比 76.3% 減が構成される。

## 3. 理論 FPS — CPU 律速 (合成フレーム実測から直接)

「重い 1 フレーム」の CPU 計算コスト = 再メッシュ 4 + ロード 8 + セーブ 2 +
実体 1 パス の加重和。**計算律速 FPS = 1000 / 合成フレーム(ms)**。

| スケール | A (ms / FPS) | B (ms / FPS) | **C (ms / FPS)** | **C vs A** | **C vs B** |
| :-- | :-- | :-- | :-- | :-- | :-- |
| **RD24** | 36.05 / 27.7 | 37.75 / 26.5 | **24.07 / 41.5** | **1.498x (+49.8%)** | **1.568x (+56.8%)** |
| **36c** | 34.63 / 28.9 | 36.22 / 27.6 | **31.21 / 32.0** | **1.110x (+11.0%)** | **1.161x (+16.1%)** |

> スケール依存性: 小規模 (36c) では Tipsify の定数項が VisGraph 定数項を上回る
> 帯で C の優位が縮小 (+11%) するが、**RD24 (公式条件) では +49.8%** と大規模
> ほど Rsift 優位が拡大する (頂点エンコード差が頂点数に比例して効くため)。

## 4. 理論 FPS 上界 — GPU 帯域律速 (理想化・天井)

実機の FPS は多くの場合 GPU 帯域 (特に統合 GPU での頂点 fetch) で律速する。
**頂点 fetch 帯域が純律速なら、FPS は帯域比の逆数まで伸びる** (理想上界)。

| スケール | C vs A 上界 | C vs B 上界 |
| :-- | --: | --: |
| **RD24** | **6.76x** (1/0.148) | **4.22x** (1/0.237) |
| **36c** | **7.56x** (1/0.132) | **4.73x** (1/0.212) |

> **誠実境界**: これは**絶対天井**であり、現実の GPU は頂点 fetch 以外にも
> (ラスタライズ / 早期 Z / フラグメントシェーダ / overdraw / フィルレート /
> テクスチャ帯域) の多数の段階を持つため、この天井には到達しない。
> 現実の FPS 向上は、**下側 = CPU 律速実測 (+49.8% @RD24)** と
> **上側 = 帯域律速天井 (6.76x)** の間に落ち、プレイヤーの律速要因の混合比で決まる。
> **統合 GPU (帯域シビア) ほど天井側、CPU ボトルネックほど下側に寄る。**

## 7. 手法と誠実な制約 (推測でない)

1. **絶対 FPS の直接計測は不可能**: sandbox は GPU 非所持・Java/Minecraft 実行不可。
   よって本書の FPS は全て**「CPU 合成フレーム実測から導く理論値」**または
   **「頂点帯域比からの理想天井」**であり、実バイナリのプロファイルではない
   (捏造・推測は行わない)。実機 FPS はユーザー環境での計測待ち。
2. **対抗 B (Sodium) は実ソース準拠の Rust 再現**: tag `mc1.21.11-0.8.13`
   (commit `9d11e9cfc5`) を file:line 引用で再現。実 jar ビルド/実行は
   sandbox ネットワーク制約で不可能 (BENCH_SODIUM_VS_RSIFT §2 証拠)。
3. **数値は全て Python 機械演算**: 端数・倍率・比率を暗算せず実測 raw 値から導出。
   合成フレームの FPS は `1000/frame_ms`。VRAM 圧縮率は `C_bytes / ref_bytes`。
4. **wave 220 HQ (cpu_saver §7 根治) の影響**: digest `004c1cf5fb17bfe8` 不変
   (挙動保存) のため、本ベンチの構造出力 (bytes/counts) は wave 220 前後で同一。
   timing 系は run 毎ジッタ (±10% 程度) するが digest 外。
5. **低スペック PC 制約**: Mesh Shader 必須技術 (Nvidium 級) は除外方針。
   12B/頂点 + indirect + palette は広範な GPU で効く軽量化軸。

## 8. 結論 (ユーザー主命題への照合)

ユーザー主命題 (2026-08-03): 「信頼できるソースから Sodium の大量項目の実測値を
取得し、それと全く同じ内容で RsGraphics のベンチを回して最低限 Sodium 以上に」

- **メモリ**: 頂点バッファ Sodium 比 **−76.3%** (233 vs 985 MB)、セクション **−92.8%**。
- **FPS (理論)**: CPU 律速で Sodium 比 **+56.8%** (41.5 vs 26.5 FPS @RD24)。
- **帯域**: 頂点 fetch 帯域 Sodium 比 −76.3% → GPU 帯域律速時の理論上界 **4.22x**。
- 計測可能全指標で C ≥ B を維持 (詳細は BENCH_SODIUM_VS_RSIFT §9.2 判定表)。

**「最低限 Sodium 以上」は RD24 (公式条件) 上で、メモリ圧縮量・理論 FPS 向向上界
ともに機械成立。実機絶対 FPS はユーザー環境検証待ち (本書は理論値)。**
